Bootstrap instructions for an agent operating against the installed KoLmafia matrix.

Authority boundary. This matrix is a retrieval and planning reference. It does not authorize KoL mutations. Resolve version-sensitive facts against installed runtime evidence or current source, and verify state after mutation.

Start here

  1. Read agent-master-index.json.
  2. Search hyper-data.json rather than scraping the human UI DOM.
  3. Match task intent against workflows and usecases, then retrieve relevant nodes.
  4. Preserve exact node IDs and mem:// pointers in reasoning/evidence packets.
  5. Expand related links when the first node is insufficient.
  6. Prefer installed runtime metadata for live facts: version, help, ashref, jsref, prefref, which, debug/session evidence, then current KoLmafia source.
  7. Do not convert observation evidence into execution authority.

Authority invariants

  • Observation evidence does not authorize execution.
  • T3 / structural-deny classifications are immutable in the learning overlay.
  • T2/mutation candidates require explicit human review outside auto-run.
  • Nested executors are classified by effective downstream action.
  • Successful tool return is not equivalent to verified state transition.

Source precedence

  1. Installed KoLmafia runtime evidence for the user's actual build.
  2. Current KoLmafia implementation source when runtime behavior needs explanation.
  3. Matrix nodes and their provenance/pointers.
  4. Historical wiki/forum/ecosystem material, explicitly treated as version-sensitive when appropriate.
